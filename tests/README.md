# Стресс-тесты экономики и логистики

Скрипты бьют по живому API и проверяют, что эксплойты закрыты.
Запускать при работающем dev-сервере. Перед прогоном стенд готовится скриптом:

```bash
npm run --silent test:stand > stand.json
```

Стенд начинается с уборки: одноразовые аккаунты прошлых прогонов удаляются, и занятые
ими колонии возвращаются в галактику — иначе конечный запас планет однажды кончается
и онбординг перестает работать. Ту же уборку можно запустить отдельно:

```bash
npm run test:cleanup
```

Удаляются только аккаунты вида `<префикс>-<суффикс>@spacemmo.local` с префиксами
из самих тестов; постоянные `admiral@` и `pilot@` защищены явным списком.

Дальше стенд приводит тестовых командиров в известное состояние (криптогривна, склад на хабе,
вне синдикатов) и печатает конфигурацию, которую принимают скрипты ниже.

```bash
node tests/auth.mjs
node tests/stress-market-fleet.mjs stand.json
node tests/stress-races.mjs stand.json
node tests/syndicates.mjs stand.json
node tests/economy-build.mjs
```

`auth.mjs` работает без конфигурации: он сам регистрирует временные аккаунты.
Секция смены пароля при этом пропускается — сервер не отдает код наружу.
Чтобы прогнать и ее, подними стенд с `AUTH_EXPOSE_RESET_TOKEN=true`; в production
флаг игнорируется, потому что роут открытый и код по чужому email раздавать нельзя.
Тесты хранилищ живут отдельно — они проверяют формулы напрямую на игровых модулях
и запускаются через tsx:

```bash
npm run test:storage
```

```bash

```


Тесты полетов сначала считают маршруты напрямую на игровых модулях, а потом идут
на живой сервер за правилами вылета и поиском по координатам. Без пути к `stand.json`
живая секция пропускается, и в итог попадает только математика.

Боевые тесты держат две разные проверки рядом. Точные утверждения идут на зерне:
одно и то же зерно обязано давать один и тот же бой. Баланс так проверить нельзя —
единичный прогон случаен, поэтому скорострел и оборона меряются серией из
десятков боев, и утверждение делается о доле побед, а не об исходе.

Тесты сами проходят авторизацию и получают JWT по данным из конфигурации.
Пароль легаси-аккаунту задается скриптом
`npm run legacy:password -- <позывной> <пароль> [email]`.

Покрытие:
- `score.ts` — формулы рейтинга: суммирование построек по уровням, линейность
  флота и обороны, вес ресурсов. Сервер не нужен.
- `oauth.ts` — проверка `id_token` Google: чужой `aud`, подпись чужим ключом,
  протухший токен, неподтвержденный email. Сервер не нужен, ключи свои.
- `auth.mjs` — регистрация, вход, защита игровых роутов, онбординг командира,
  уникальность позывного, смена пароля и заглушки OAuth.
- `syndicates.mjs` — матрица прав ролей (участник не может одобрять заявки,
  исключать и распускать; офицер разбирает заявки, но не правит составом),
  общий банк с атомарными пожертвованиями и дипломатия альянсов.
  Синдикаты в конце распускаются, стенд возвращается в исходное состояние.
  Покрыта и передача лидерства, и право офицера исключать только рядовых.
- `stress-market-fleet.mjs` — валидация ордеров и сделок (отрицательные и дробные
  значения, Infinity, текст, превышение баланса), гонки залога товара и криптогривны,
  аномальные вылеты флота, боевые профили классов кораблей и обороны.
- `stress-races.mjs` — конкурентное частичное исполнение ордера, двойная отмена,
  два ордера на грани баланса.
- `economy-build.mjs` — очереди строительства, стоимость и требования построек.
- `commander.ts` — плазма в трюмах, пороги старения разведданных (включая скрытие
  флота и склада на сервере, а не только в интерфейсе), нормализация старых снимков,
  а по живому API — валидация и детерминированность симулятора и полный CRUD шаблонов
  флотов вместе с проверкой, что чужой шаблон не виден и не правится.
- `combat.ts` — боевой движок: баланс юнитов, раунды и восстановление щитов,
  скорострел и боевые технологии, сценарии «крейсер против роя», «пустая база»
  и «обломки», восстановление обороны. Отдельный раздел меряет баланс скорострела
  против обороны: равный по стоимости флот ее не берет, двукратного перевеса мало,
  четырехкратный снимает — иначе строить оборону было бы незачем.
  Бой случаен, поэтому проверяется двумя способами: с подставленным зерном сверяется
  точный исход, а баланс и шанс восстановления обороны — по распределению на серии.
- `fleets.ts` — полеты: скорость по самому медленному кораблю, влияние двигателей,
  дистанция по орбитам, гиперпрыжок и его удешевление гипердвигателем, расход
  в один конец у рейсов без возврата, типы миссий. По живому API — правила вылета
  дислокации и поиск планеты по координатам вместе с его отказами (404, 400, 401).
- `assets.ts` — соответствие растровых файлов типам объектов. Нужен потому, что
  несовпадение имени ничего не ломает: карточка молча показывает заглушку, и ошибку
  видно только глазами. Тест отличает «картинки пока нет» от «файл лежит мимо
  конвенции», плюс сторожит сам механизм: заглушку, отсутствие lazy-загрузки
  и удаленные из спрайта крупные SVG.
- `debris.ts` — формула обломков (30% стоимости, потери обеих сторон, оборона),
  характеристики переработчика и главное — атомарность сборки: два флота,
  забирающие поле одновременно, не должны его задвоить.
- `admin.ts` — доступ к `/api/admin/*` (аноним 401, обычный игрок 403 — проверяется
  весь раздел разом, чтобы поймать путь, повешенный мимо `requireAdmin`), God Mode
  над ресурсами, зданиями, технологиями и флотом, валидация ввода и главное —
  выданное не затирается ближайшим сбросом состояния из памяти тика.
- `mail.ts` — приватность ящика (чужое письмо нельзя прочитать, удалить или задеть
  массовым «прочитать все» даже по прямому id), валидация переписки и формулировки
  системных отчетов: зеркальность боевых писем, координаты и исход в их нагрузке,
  отчеты разведки и экспедиций, письма логистики (доставка себе и чужому, состав
  и груз дислокации, молчание пустого возврата).
- `storage.ts` — вместимость хранилища, остановка добычи на полном складе, корректный
  догон офлайна (включая разбивку периода на отрезки) и механика «сейфа» при грабеже:
  несгораемый объем, пропорциональный вывоз излишка и ограничение трюмами.

- `bot.ts` — решения бота как чистая функция: порядок застройки и науки,
  состав флота и обороны, щит новичка, торговля. Сервер не нужен — `decide`
  принимает снимок и возвращает намерения, поэтому проверяется без базы.
- `budget.ts` — учет обращений к языковой модели: общая дневная норма на всех
  ботов, попытка считается независимо от ответа сервиса, потолки переписки.
  Счетчик лежит в `Bot.memory` и переживает изменения игры, поэтому отдельно
  проверяется, что мусор в нем читается как ноль, а не как безлимит.
