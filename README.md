# Space Strategy MMO — Фаза 1 + Этапы 6-7

Браузерная мультиплеерная экономическая стратегия в космосе.
Реализованы **Этап 1** (фундамент, генерация системы, базовая добыча),
**Этап 2** (дерево технологий, верфь, потребление энергии, серверные таймеры),
**Этап 3** (карта системы, логистика флота, топливо, туман войны),
**Этап 4** (криптогривна, торговый хаб, склады и биржевой стакан)
**Этап 5** (стационарная оборона, бой, грабеж, отчеты и дипломатия)
**Этап 6** (макро-карта галактики, антиматерия, гиперпрыжки, аномалии)
и **Этап 7** (экспедиции в глубокий космос и PvE-события).

## Стек
Node.js + TypeScript · Express · Socket.IO · PostgreSQL (Prisma 7 + pg adapter) · HTML/JS/CSS · Docker

## Запуск

```bash
npm install
cp .env.example .env        # укажи DATABASE_URL
npx prisma migrate dev      # применить миграции
npm run generate            # сгенерировать стартовую систему (3-5 планет)
npm run dev                 # http://localhost:3000
```

## Что реализовано (Этап 7)
- **Экспедиции:** миссия в «глубокий космос» — абстрактную 16-ю позицию, которая есть
  у каждой системы. В свою систему флот идет на дейтерии, в чужую — гиперпрыжком
  на антиматерии, по тем же правилам логистики.
- **Технология «Астрофизика»:** задает число одновременных экспедиций (1 → 1, 4 → 2, 9 → 3),
  увеличивает находки, снижает долю пустых вылетов и дает шанс уйти от засады.
- **Событийный движок** ([expeditions.ts](src/game/expeditions.ts)): бросок кубика по весам —
  мертвая тишина, заброшенный груз (металл, кристаллы или антиматерия, не больше свободных
  трюмов), уклонение от засады или бой с пиратами. Пираты генерируются под силу флота
  и считаются уже существующим боевым модулем. Генератор случайных чисел передается
  снаружи, поэтому любой исход воспроизводим в тестах.
- **Отчеты об экспедициях:** готовый текст события, добыча и потери — в интерфейсе
  и в `GET /api/war`.
- **Фикс аномалии:** искажение времени у черной дыры теперь замедляет и постройку
  на верфи (корабли и оборону), а не только здания с исследованиями.

## Что реализовано (Этап 6)
- **Галактика:** генератор создает 10-15 систем на координатной сетке, у каждой свой
  торговый хаб. Скрипт идемпотентен: уже существующие системы и колонии не трогает,
  а только дополняет галактику и заводит недостающие хабы.
- **Макро-карта:** переключатель «Система / Галактика». На макро-карте видны все системы
  с координатами, классом звезды и аномалией; клик по системе открывает ее микро-карту
  с тем же туманом войны — планеты видно как объекты, содержимое только после разведки.
- **Антиматерия:** новый ресурс и «Синтезатор антиматерии» — самая дорогая постройка базы
  с огромным расходом энергии. Синтез идет на порядки медленнее обычной добычи, потому что
  это топливо для прыжков, а не сырье.
- **Технологии:** «Гиперпространственная физика» (открывает синтезатор) и «Гипердвигатель»
  (открывает прыжки; каждый уровень ускоряет прыжок и снижает расход антиматерии).
- **Раздельная логистика:** внутри системы флот идет на обычной тяге и жжет дейтерий,
  между системами выполняет гиперпрыжок на антиматерии. Время и расход прыжка зависят
  от расстояния между системами на макро-карте.
- **Аномалия «Черная дыра»:** 1-2 системы галактики. Эффект «Искажение времени» для всех
  планет системы: синтез антиматерии +50%, стройка и исследования на 30% дольше.

## Что реализовано (Этап 5)
- **Стационарная оборона:** ракетная установка и лазерное орудие строятся на верфи
  собственной очередью, требуют ресурсов, времени и постоянно потребляют энергию
  (дефицит бьет по добыче так же, как от шахт). Летать не может.
- **Миссия «Атака»:** новый тип вылета. Разрешена только при активной войне и только
  по чужой колонии; флоту нужны боевые корабли или транспорты.
- **Боевой модуль** ([combat.ts](src/game/combat.ts)): мгновенный расчет без раундов.
  Мощь стороны = суммарный урон × живучесть (корпус + щиты). Побеждает сторона с большей
  мощью, при равенстве держится защитник. Проигравший теряет всё, победитель — долю,
  равную отношению сил. Расчет детерминированный: одинаковый ввод дает одинаковый бой.
- **Грабеж:** победивший атакующий вывозит до половины склада побежденного, но не больше
  вместимости уцелевших трюмов. Груз довозится домой обычным возвратным рейсом.
- **Отчеты о боях:** обе стороны видят один бой со своей стороны — состав, мощь, потери
  по каждому типу, награбленное и вердикт.
- **Дипломатия:** объявление войны и мир. Себе войну объявить нельзя, атаковать себя тоже.

## Что реализовано (Этап 4)
- **Криптогривна** — глобальная валюта аккаунта, стартовый баланс 1000 ₴, виден в шапке интерфейса.
- **Торговый хаб** — нейтральная станция на орбите у звезды, появляется на карте системы и доступна
  как цель полета (создается скриптом генерации идемпотентно).
- **Физические склады:** товар попадает на хаб только транспортным флотом (миссия «Доставка на хаб»).
  Что не влезло в склад — возвращается домой в трюмах. Обратный рейс «Вывоз с хаба» забирает товар назад.
- **Расширение склада:** уровень склада поднимает вместимость (5000 → 8000 → …), платится металлом
  и кристаллами, которые уже лежат на хабе.
- **Биржевой стакан:** ордера на покупку и продажу металла и кристаллов за криптогривну.
  Продажа блокирует товар на складе, покупка — деньги, поэтому продать или потратить одно и то же
  дважды нельзя. Ордера исполняются частично, снятие возвращает заблокированное.
  Сделки идут в одной транзакции БД и пишутся в журнал.

## Что реализовано (Этап 3)
- **Карта системы (микро-уровень):** SVG-схема с звездой и орбитами, наведение показывает данные
  с учетом тумана войны, клик выбирает планету и открывает панель отправки флота.
- **Логистика:** флот летит между планетами с реальным временем в пути. Скорость определяет самый
  медленный корабль, «Реактивный двигатель» ускоряет флот на 10% за уровень.
- **Грузоподъемность:** транспорт везет 2000 единиц, истребитель 50, зонд ничего.
  Перегруз трюмов сервер отклоняет.
- **Топливо:** каждый вылет сжигает дейтерий со склада отправления. Расход зависит от состава флота
  и времени в пути (туда и обратно), списывается при отправке.
- **Туман войны:** своя планета видна целиком и в реальном времени; чужая — только название, орбита,
  тип и размер. После прилета зонда сохраняется снимок (владелец, богатство, шахты, склад, флот),
  который стареет и не обновляется сам — виден возраст данных.
- **Прилеты обрабатываются глобально:** груз доходит до получателя и корабли возвращаются, даже
  если отправитель и получатель офлайн; для игроков в памяти правится состояние, иначе — инкремент в БД.

## Что реализовано (Этап 2)
- **Дерево технологий:** 4 технологии с иерархией требований, изучаются в лаборатории за время и ресурсы.
  «Энергетика» (+2% энергии/ур.), «Вычислительная техника» (-3% времени исследований/ур., открывает зонды),
  «Горное дело» (+2% добычи/ур.), «Реактивный двигатель» (открывает транспорты и истребители).
  Технологии общие для игрока, одновременно изучается одна.
- **Верфь:** 3 класса кораблей (зонд, малый транспорт, легкий истребитель) с требованиями по верфи и технологиям.
  Заказы встают в очередь, корабли выходят поштучно, уровень верфи ускоряет постройку.
- **Потребление энергии:** здания тратят энергию; если выработки не хватает, добыча всех шахт падает
  пропорционально дефициту (`efficiency = output / usage`).
- **Серверные таймеры:** стройка зданий, исследования и очередь верфи считаются от абсолютных меток
  времени в Game Loop. Процессы идут, пока игрок офлайн, и переживают перезапуск сервера;
  добыча за офлайн начисляется по отрезкам между завершениями таймеров.
- **Интерфейс:** вкладки «Инфраструктура / Исследования / Верфь», прогресс-бары активных таймеров,
  индикатор эффективности энергии, ангар и очередь верфи.

## Что реализовано (Этап 1)
- **Схемы БД:** `User`, `SolarSystem`, `Planet` (коэффициенты Металл/Кристаллы/Дейтерий/Инсоляция), `Base`
  (+ `BuildJob`, `Research`, `ResearchJob`, `Ship`, `ShipJob` на Этапе 2,
  `Fleet` и `PlanetScan` на Этапе 3, `TradeHub`, `HubStorage`, `MarketOrder`, `Trade` на Этапе 4,
  `Defense`, `DefenseJob`, `BattleReport`, `WarDeclaration` на Этапе 5).
- **Генерация:** одна стартовая система, 3-5 уникальных планет с типами и разбросом богатства.
- **Авторизация (заглушка):** вход по позывному, новому игроку выдается свободная планета и колония.
- **Командный центр:** дашборд со списком баз, параметрами планеты, ресурсами и инфраструктурой.
- **Game Loop:** изолированный серверный тик раз в 1 секунду, начисление ресурсов, догон офлайн-периода
  (до 24 ч), пакетная запись в БД раз в 10 тиков, push состояния в клиент через WebSocket.
- **Постройка:** проверка ресурсов и требований строго на сервере.

## API
| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/auth/login` | вход по позывному (заглушка Этапа 1) |
| GET | `/api/state` | состояние игрока: базы, очереди, технологии, флот |
| POST | `/api/bases/:id/build` | поставить здание в стройку |
| POST | `/api/bases/:id/research` | запустить исследование |
| POST | `/api/bases/:id/ships` | заказать корабли на верфи |
| GET | `/api/galaxy` | макро-карта: все системы с координатами |
| GET | `/api/map?systemId=` | карта системы (по умолчанию — родной) с туманом войны |
| POST | `/api/bases/:id/fleets/preview` | предрасчет маршрута: время, топливо, трюмы |
| POST | `/api/bases/:id/fleets` | отправить флот (транспорт, разведка, рейс на хаб) |
| GET | `/api/market` | склад на хабе, стакан, свои ордера, журнал сделок |
| POST | `/api/market/storage/upgrade` | расширить склад на хабе |
| POST | `/api/market/orders` | выставить ордер на покупку или продажу |
| POST | `/api/market/orders/:id/fill` | исполнить чужой ордер |
| DELETE | `/api/market/orders/:id` | снять свой ордер |
| POST | `/api/bases/:id/defenses` | заказать стационарную оборону |
| GET | `/api/war` | дипломатия и отчеты о боях |
| POST | `/api/war/declare` | объявить войну |
| POST | `/api/war/peace` | заключить мир |

Экспедиция отправляется тем же `POST /api/bases/:id/fleets` с миссией `EXPEDITION`:
без цели — в глубокий космос родной системы, с `targetSystemId` — в чужую.

## Качество кода
- Строгий TypeScript: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`.
  Отдельный прогон `npm run audit` добавляет `noUnusedLocals` и `noUnusedParameters`.
- Ответы REST API типизированы через `Response<...>` ([types/api.ts](src/types/api.ts)),
  события Socket.IO — через типовые контракты ([types/socket.ts](src/types/socket.ts)):
  расхождение между сервером и клиентом ловит компилятор.
- Игровые правила вынесены в чистые модули без обращений к БД, поэтому формулы
  проверяются отдельно от инфраструктуры (`npm run check:rules`).

## Надежность
- Гонки на бирже закрыты условными `UPDATE` (списание проходит, только если товар или
  криптогривна реально есть), пополнение склада хаба проверяет вместимость в самом запросе.
- Прилет флота, бой и возврат идут одной транзакцией с изменением статуса флота, поэтому
  жесткий перезапуск между шагами не задваивает начисления и не теряет корабли.
- Ввод разбирается строго: дробные и отрицательные значения отклоняются, а не округляются.
- Регрессия проверяется скриптами из [tests/](tests/README.md) — 50 проверок.
